# submit 스킬

리뷰와 반영이 모두 끝난 코드를 정리하고 커밋/푸시한다. 코드 리뷰나 수정은 이 스킬의 역할이 아니다 (리뷰는 `reviewer` 서브에이전트가 담당).

## 1. 대상 파일 확인
- `Solving/main.cpp` 또는 `SolvingCsharp/Program.cs` 중 어떤 파일인지 확인한다. 사용자가 직접 지정하지 않았다면 먼저 물어본다.
- 파일 최상단 주석에서 문제 출처와 이름을 파악한다 (예: `// 백준 1517번 : 버블 소트`).
- 주석에서 출처/이름을 파악할 수 없으면 추측하지 말고 사용자에게 확인한다.

## 2. 파일 이름 규칙에 따라 저장
CLAUDE.md의 File Naming Convention을 그대로 따르되, 확장자별 저장 위치는 다음과 같다.

| 출처 | 형식 | 예시 |
|------|------|------|
| 백준 | `백준[번호]번_[문제명].cpp` | `백준1517번_버블 소트.cpp` |
| 프로그래머스 | `프로그래머스(L[레벨])_[문제명].cpp` | `프로그래머스(L3)_아이템 줍기.cpp` |
| 카카오 | `카카오_[연도]_[문제명].cpp` | `카카오_2023_표현 가능한 이진트리.cpp` |

**규칙:**
- 문제명은 원래 제목 그대로 (공백 유지, 특수문자 제거), "번" 반드시 포함(백준 한정), 구분자는 `_`.
- 저장 위치: `.cpp` 파일 → `Cpp_02/`, `.cs` 파일 → `Csharp_01/success/`.
- 현재 작업 파일의 최종본을 그대로 저장한다.
- 같은 이름의 파일이 이미 있으면 덮어쓰지 말고, 그 사실을 사용자에게 알린다 (임의로 판단하지 않음).

## 3. 커밋 및 푸시
- 새로 생성한 파일을 `git add`.
- 커밋 메시지 형식: `[출처] : [문제명] ([알고리즘 태그, 콤마 구분])`
  - 예: `프로그래머스(L3) : 고고학 최고의 발견 (DP, 우선순위큐)`
  - 알고리즘 태그는 리뷰/대화 과정에서 파악한 내용을 바탕으로 정리한다. 모호하면 사용자에게 확인한다.
- `git push`는 CLAUDE.md 규칙대로 승인 문구를 붙여 사용자에게 확인받는다.
  - 예: `git push origin master (원격 브랜치에 푸시할까요?)`
